# Редактор графа УДС (OSM)

Веб-редактор уличной сети: открывает `.osm`, показывает в 2D поверх карты, даёт править узлы, дороги,
направления, полосы, светофоры, мосты, подсвечивает ошибки и сохраняет `.osm`, пригодный для SUMO / MATSim / Webots.

Без бэкенда: всё работает в браузере (Vite + React + TypeScript, Canvas 2D).

## Запуск

```bash
npm install
npm run dev          # http://localhost:5173
```

Без установки Node (Docker):

```bash
docker compose up --build   # http://localhost:8080
```

Прочее:

```bash
npm test                              # тесты (парсер, undo/redo, валидатор, прогон через SUMO)
npm run build                         # продакшен-сборка в dist/
npm run check:sumo -- file.osm        # проверить файл через SUMO netconvert
npm run stats -- file.osm             # статистика транспортного графа и проблем
```

### Транспортный граф

`src/core/graph.ts` строит из документа направленный граф только для дорог машин. Узел графа — перекрёсток или
конец дороги, ребро — отрезок между ними (двусторонняя дорога = 2 ребра, `oneway` = 1; кольцо и магистраль
односторонние по умолчанию). Граф нужен валидатору, а также удобен для 3D и интерполяции Z вдоль цепочки рёбер.

```ts
const g = buildGraph(store.doc)          // или graphFor(store.doc, store.version) — с кэшем
const a = analyze(g)                     // a.main, a.traps, a.noEntry, a.detached
```

Для проверки в SUMO: `pip install eclipse-sumo` (в venv) или задайте `SUMO_HOME`. Тест `sumo.test.ts` пропускается, если SUMO не найден.

## Оформление и демонстрация

- **Тёмная тема «центр управления»** (по умолчанию) и светлая — кнопка ☀/☾ в шапке, выбор запоминается. В тёмной теме
  подложка затемняется, магистрали светятся, плавающие панели — «стекло».
- **Живое движение** — пульт внизу карты: «▶ Движение», ускорение времени ×1…×20, число машин 50…1000, сводка
  (машин, средняя скорость, сколько стоят, время). Машины едут по транспортному графу с учётом `oneway` и ограничений
  скорости, держат дистанцию, на перекрёстках выбирают направление случайно и **стоят на красный по планам светофоров**
  (без плана — план по умолчанию). Цвет машины в 2D — скорость (красный стоит, зелёный едет), у светофоров горят сигналы
  подходов. Машины едут **по полосам**: число полос из `lanes` (`lanes:forward/backward`), встречные — слева от осевой,
  дистанция держится внутри своей полосы, на перекрёстке машина по возможности остаётся в своей полосе.
  Это демонстрация, не замена SUMO. Модель: `src/core/traffic.ts`.
- **Производительность:** машины рисуются на отдельном прозрачном слое (кадр движения не перерисовывает сеть); сеть
  рисуется с отсечением всего, что за экраном, линии одного стиля — одним вызовом, координаты узлов и рамки дорог
  кэшируются до следующей правки, тёмная подложка готовится один раз на тайл. На example.osm при 600 машинах: перерисовка
  сети при сдвиге ≈ 7 мс, кадр машин ≈ 2–3 мс, шаг модели ≈ 0,2 мс (в dev-режиме журнал — `__mapLog` в консоли).
- **3D:** тени от солнца, небо и туман, режим **☾ Ночь** (луна, фонари вдоль улиц, светящаяся разметка, фары и
  стоп-сигналы машин, горящие сигналы светофоров), **🎥 Облёт** — камера плавно кружит (любой клик останавливает).
- **Обзор** (вкладка справа): длина сети и полос, перекрёстки и связность, светофоры (с планом), остановки (привязанные),
  пешеходные и трамвайные пути, ошибки и предупреждения, длина по классам дорог и по ограничению скорости
  (кнопка «Таблица» показывает цифры), живой график средней скорости во время движения. Расчёт: `src/core/networkStats.ts`.

## Как пользоваться

- **Открыть** (Ctrl+O) или **Пример** — загрузить `.osm`.
- Колесо или кнопки **＋ / −** справа вверху — масштаб, перетаскивание — сдвиг карты, **⛶** — показать всю сеть.
  Файл `.osm` можно просто перетащить в окно.
- Внизу слева — **масштабная линейка** (учитывает широту) и **миникарта**: она появляется при приближении, показывает
  всю сеть и рамку текущего вида; клик или перетаскивание по ней перемещает вид. Внизу справа — координаты курсора.
- Меню **Вид** (пешеходные дорожки, подложка, адрес тайлов) и **Экспорт** (только дороги, пешеходные, метаданные) — в шапке.
- Справа — атрибуты, шаблоны дорог, теги.

### 3D

Кнопка **3D** в шапке (клавиша **3**, назад — **2**) открывает объёмный просмотр на three.js: дороги шириной по числу полос,
мосты с настилом и опорами, светофоры, здания (`building`, этажность по `building:levels`). Вращение — левая кнопка,
сдвиг — правая, колесо — масштаб. Клик по дороге выбирает её, так что теги и высоту можно править в панели справа
и сразу видеть результат. Ползунок «Высота ×N» преувеличивает высоты только для показа (мост 6 м в 2 км почти не виден).

**Высоты (Z).** Высота узла — тег `ele` (метры). Если его нет, мост поднимается на `layer × 6 м` и плавно сходит на нет у концов
(сглаженная кривая, продолжение моста в соседней дороге не проседает), тоннель опускается. В панели выбранной дороги блок
**«Высота (Z)»**: задайте высоту начала и конца и нажмите «Плавный переход» — высоты узлов растут линейно по расстоянию
и записываются в `ele` (показывается уклон, предупреждение при > 10 %). Логика в `src/core/elevation.ts`.

### Полосы и разметка

Число полос берётся из `lanes` (и `lanes:forward` / `lanes:backward`), без тегов: односторонняя дорога — 1 полоса,
двусторонняя — по полосе в каждую сторону, служебные проезды — 1. На приближении (когда полоса шире ~5 px) дорога рисуется
реальной ширины (полоса 3,2 м) с белым **пунктиром между полосами**: 3 полосы — 2 пунктира, 2 полосы — один. У двусторонней
дороги встречная линия **жёлтая** (по `lanes:forward/backward`, правостороннее движение). То же в 3D на полотне дороги.
Логика: `laneInfo` в `src/core/roads.ts`, смещение и нарезка линий в `src/core/geo.ts`.

### Пешеходные дороги

В инструменте **D** («＋ Дорога») в списке типов есть группа **«Пешеходные»**: пешеходная дорожка (`highway=footway`), пешеходная улица
(`highway=pedestrian`), лестница (`highway=steps`) и пешеходный переход через проезжую часть (`highway=footway` + `footway=crossing`,
по такой SUMO строит пешеходный переход; концы и середина ставятся на узлы проезжей дороги). При выборе такого типа сами включаются
показ пешеходных дорожек и галочка экспорта «Добавить пешеходные», иначе по умолчанию в `.osm` для симулятора идут только дороги
для машин. Пешеходные дороги не входят в транспортный граф для машин и не влияют на проверки связности.

### Слои и навигация

Кнопка **«Слои»** справа внизу карты включает и выключает объекты: дороги для машин, пешеходные, трамвайные пути,
разметку полос, светофоры, переходы, остановки, отметки проблем, номера узлов и подложку. Инструменты слева подписаны
(Выбор, Дорога, Узел, Светофор, Остановка, Переход) и показывают горячую клавишу.

**Номера узлов** (слой «Номера узлов») рисуются плашками только у узлов видимой сети — дорог, путей и остановок, без
зданий — и не налезают друг на друга. На мелком масштабе подписывается только выбранный узел.

### Трамвайные пути

В инструменте **D** в группе «Рельсовые» есть «Трамвайные пути» (`railway=tram`, колея 1524 мм, контактная сеть).
Пути из файла тоже рисуются (в 2D — тёмная линия со «шпалами», в 3D — балласт и два рельса). При экспорте «только дороги»
трамвайные пути сохраняются вместе с дорогами: SUMO импортирует их как `railway.tram` (проверено тестом).

### Остановки: привязка к узлу

Каждая автобусная остановка должна быть привязана к узлу дороги. Непривязанные остановки попадают в «Проблемы» с кнопкой
«Привязать к узлу № …» (ближайший узел дороги; если он ближе 40 м, исправление входит в «Исправить автоматически»).
У выбранной остановки (или её опорного узла) в панели справа есть поле **«Номер узла дороги»**: можно привязать
остановку к любому узлу по номеру или перепривязать уже привязанную. Значок «А» перетаскивается мышью.

### Светофорное регулирование (по схеме Visum)

Иерархия: **светофорный узел → сигнальные группы → направления движения**. Выберите узел-светофор — в панели справа блок
«Светофорное регулирование»:

- **Создать план** — фиксированное время: подходы делятся на оси (попутные и встречные вместе), каждая ось — своя группа,
  цикл делится поровну, между группами — межзелёный интервал. Направления (въезд × выезд, без разворотов, с учётом `oneway`)
  считаются автоматически и подписаны: «Колхозная улица → Проезд 780751420 (налево)».
- **Параметры цикла:** длительность цикла, сдвиг фаз (offset), жёлтый, межзелёный. **Группы:** имя, момент включения и
  выключения зелёного (секунды внутри цикла, можно через конец цикла), галочки направлений.
- **Диаграмма цикла** (зелёный / жёлтый / красный по группам) и **расчёты:** доля зелёного g/C и равномерная задержка по Вебстеру
  (интенсивности в OSM нет, поэтому степень насыщения принята 0,8).
- **Проверки:** конфликтующие группы не горят зелёным одновременно (пересекающиеся направления и слияние в одну дорогу; левый
  поворот против встречного — с уступкой), межзелёный интервал выдержан, каждое направление в какой-то группе, жёлтый ≤ межзелёного.
  Ошибки плана видны и в «Проблемах».
- **Зелёная волна:** укажите опорный светофор и скорость — сдвиг рассчитается по расстоянию по дорогам (кратчайший путь)
  так, чтобы главная (первая) группа включалась к приезду пачки машин.
- На карте у выбранного светофора направления рисуются стрелками в цветах групп.

План хранится тегами `polyhack:signal:*` на узле (значения ≤ 255 символов, как требует OSM) и сохраняется в `.osm`.
Для **SUMO**:

```bash
npm run export:sumo -- файл.osm out/sumo
```

Команда собирает сеть (`netconvert`), сопоставляет каждое соединение светофора SUMO с направлением плана и пишет
`signals.add.xml` с программами `tlLogic` (G — зелёный, g — зелёный с уступкой, y — жёлтый, r — красный, offset — сдвиг)
и `simulation.sumocfg`. Запуск: `sumo-gui -c out/sumo/simulation.sumocfg`. Тест проверяет, что SUMO загружает программу и
проигрывает два цикла без ошибок. Адаптивное регулирование и внешние процедуры (RiLSA, Python) не реализованы.

### Светофоры и пешеходные переходы

Инструменты **T** (светофор) и **C** (пешеходный переход) — это обычные правки OSM, они **попадают в `.osm`**.
Клик по узлу ставит тег на него, клик по дороге вставляет в неё новый узел (одним шагом отмены) с тегом:
светофор — `highway=traffic_signals`, переход — `highway=crossing` + `crossing=uncontrolled`. Если на узле уже есть
одно из двух, теги дополняются (`crossing=traffic_signals`), а не затираются. SUMO строит по таким узлам светофорные
перекрёстки (это проверено тестом). Значки на карте — просто отрисовка тегов узла: светофор рисуется иконкой, переход «зеброй»
поперёк дороги (и в 2D, и в 3D). Логика: `placeRoadFeature` и `featureTags` в `src/core/ops.ts`.

### Инструменты

Линейные дороги автоматически разделяются на отрезки между соседними узлами при загрузке и редактировании. У каждого отрезка свои свойства; границы показаны в панели атрибутов. Дорожные площади с `area=yes` сохраняют замкнутую форму.

**Остановка (B).** Первый клик по дороге выбирает опорный узел — всегда существующий узел дороги (при клике между узлами берётся ближайший, новый узел в дорогу не вставляется). Второй клик: по существующей остановке из OSM (белый значок «А») — она привязывается без создания нового узла, сохраняя своё название и теги; по пустому месту — создаётся новое место посадки. При удалении опорного узла остановка из OSM остаётся на карте (в связке `stop_area` для этого стоит пометка `polyhack:platform=existing`). После создания включается выбор объектов. Потяните значок остановки, чтобы переместить место посадки; линия показывает связь с прежним опорным узлом. Действие отменяется одним Ctrl+Z.

| Клавиша | Инструмент / действие | Как работает |
|---|---|---|
| **V** | Выбрать | Клик — выбрать дорогу (при приближении — узел). Выбранный узел перетаскивается; если отпустить над другим узлом — узлы склеиваются |
| **D** | ＋ Дорога | Клики ставят точки, тип дороги — в списке рядом (шаблон тегов). Клик по узлу присоединяет, клик по дороге врезается и делает перекрёсток. Закончить: клик по последней точке или **Enter**; **Backspace** — убрать точку, **Esc** — отмена |
| **N** | ＋ Узел | Клик по дороге ставит на неё узел (для изгиба геометрии) |
| **T** / **C** | Светофор / Переход | Узел с тегом `highway=traffic_signals` / `highway=crossing` на дороге (сохраняется в .osm) |
| **S** | Разрезать | Для выбранного узла: режет проходящие через него дороги на две |
| **R** | Развернуть | Меняет направление выбранной дороги |
| **Del** | Удалить | Удаляет выбранную дорогу или узел вместе с зависимостями (запреты поворотов, лишние узлы) |
| **Ctrl+Z / Ctrl+Shift+Z** | Отмена / возврат | Любая операция — один шаг |

Подсветка при наведении в режимах рисования: зелёное кольцо — привязка к узлу, синее — к дороге.
Операции лежат в `src/core/ops.ts` (`drawRoad`, `insertNodeOnWay`, `splitAtNode`, `deleteNode`, `deleteWay`, `mergeNodes`),
шаблоны дорог — в `src/core/templates.ts`.
- Вкладка **Проблемы** — найденные ошибки; клик по строке переводит карту к месту. У проблемы могут быть кнопки:
  **Исправить автоматически** (удалить битые запреты поворотов, склеить дубли узлов; один шаг отмены),
  ручное исправление (например, «Удалить участок» для изолированного куска) и **Скрыть** (не считать проблемой до перезагрузки файла,
  нужно для «ловушек» на краю обрезанной карты). Исправления описаны в `src/validate/fixes.ts`: добавьте поле `fix` в `Issue`.
- **Сохранить** (Ctrl+S) — проверка + скачивание `<имя>.edited.osm`. Опции экспорта: только дороги, + пешеходные, метаданные.

## Устройство

```
src/core/types.ts      КОНТРАКТ: OsmNode / OsmWay / OsmRelation / OsmDocument
src/core/parse.ts      .osm (XML) → OsmDocument
src/core/serialize.ts  OsmDocument → .osm; экспорт «только дороги»
src/core/store.ts      хранилище + транзакции + undo/redo (store.commit)
src/core/ops.ts        операции редактирования (moveNode, reverseWay, splitWayAt, ...)
src/core/roads.ts      классы дорог, стили, направление (oneway)
src/core/geo.ts        Web Mercator, расстояния
src/core/graph.ts      транспортный граф: buildGraph, SCC (Тарьян), analyze (ловушки / нет въезда / отдельные куски)
src/validate/index.ts  валидатор: массив CHECKS, каждая проверка (doc) => Issue[]
src/ui/MapView.tsx     Canvas-карта: отрисовка, pan/zoom, выбор, перетаскивание узла
src/ui/tiles.ts        подложка (растровые тайлы)
src/ui/overlays.ts     масштабная линейка (scaleBar) и миникарта (Minimap)
src/ui/scene3d.ts      построитель 3D-сцены (buildScene): ленты дорог, мосты, здания, светофоры
src/ui/View3D.tsx      3D-просмотр: камера, выбор кликом, настройки (грузится лениво)
src/ui/ElevationEditor.tsx  редактор высоты выбранной дороги
src/core/elevation.ts  высоты узлов, профиль моста, плавный переход Z
src/core/signals.ts    светофорное регулирование: направления узла, план, проверки, задержка, зелёная волна
src/core/sumoSignals.ts  план → программы светофоров SUMO (tlLogic)
src/ui/icons.tsx       иконки
src/ui/AttributePanel.tsx  панель атрибутов и шаблоны
src/ui/IssuesPanel.tsx     список проблем
src/App.tsx            тулбар, горячие клавиши, сохранение
```

Правило правок: любая правка — через `store.commit('название', tx => { tx.setNode(...) })`.
Транзакция сама запоминает «было/стало», поэтому undo/redo работает без дополнительного кода.
Новые объекты получают уникальные положительные id (`tx.newId()`). При открытии файлов прежней версии временные отрицательные id заменяются с обновлением всех ссылок.

В режиме разработки store доступен в консоли браузера: `__store.doc.ways`, `__store.undo()`.

| 3 | Инструменты | `src/ui/MapView.tsx`, `ops.ts` | Рисование дороги, добавление узла на дорогу, соединение, разрез, hotkeys |
| 4 | Панель атрибутов | `src/ui/AttributePanel.tsx` | Полосы, `turn:lanes`, светофоры, мосты (`bridge`+`layer`), шаблоны, автозаполнение |
| 5 | Валидатор | `src/validate/*`, новый `src/core/graph.ts` | Транспортный граф, сильная связность с oneway, тупики, пересечения без узла |
| 6 | Подложка, Docker, 3D | `src/ui/tiles.ts`, `Dockerfile` | Своя подложка/картинка, образ, 3D (three.js) и плавный Z (`ele`) |

Чтобы не ломать друг другу файлы: свой модуль — свои файлы, контракт `src/core/types.ts` менять только по договорённости.

## Что отдаём симуляторам

Экспорт по умолчанию — только дороги для машин + запреты поворотов, у которых остались все участники.
Здания и маршруты общественного транспорта отбрасываются (их обрезка по рамке даёт кучу предупреждений в SUMO).
Служебные атрибуты (`user`, `changeset`, ...) по умолчанию не пишутся.
Проверено: SUMO `netconvert` проходит на исходном файле и на файле после правок и экспорта.

## Подложка и условия использования

По умолчанию подложка — тайлы OpenStreetMap (годится для демо; для нагрузки нужен свой тайл-сервер).
Любой другой источник — шаблон URL в поле рядом с чекбоксом «подложка».
Яндекс/Google/2ГИС: условия использования ограничивают кэширование и сохранение тайлов,
подключать их надо со своим ключом через официальное API.
